## 1. 암호 게이트

프롬프트 12번: *"눈 깜빡이 버튼을 통해 내가 타이핑치는 암호를 보여주거나 가리거나."*

### 1.1 화면

`--deep` 배경 풀스크린. 중앙에 카드 하나 — 한 화면에 한 가지 일.

```
ADMIN                                   ← --t-label
관리자 인증

┌──────────────────────────────┬───┐
│ ••••••••••••                 │ 👁 │   ← 눈 토글
└──────────────────────────────┴───┘
[ 확인 ]

이 화면은 데모용입니다. 실제 인증이 아닙니다.
```

### 1.2 눈 토글 사양

- `<input type={visible ? 'text' : 'password'}>` 전환
- 아이콘: **인라인 SVG 2종**(eye / eye-off) — 이모지 금지 (디자인 시스템 §Don't). 위 도식의 👁 는 설명용
- 44×44 히트 영역, 입력창 우측 내부 정렬
- `aria-label` 동적: "비밀번호 표시" ↔ "비밀번호 숨기기", `aria-pressed={visible}`
- `type` 전환 시 **커서 위치를 유지**한다 (`selectionStart/End` 복원) — 안 하면 커서가 끝으로 튄다
- 토글은 `<button type="button">` — `type` 생략 시 폼이 제출된다 (흔한 버그)
- 상태는 저장하지 않는다 (항상 가림으로 시작)

### 1.3 인증 동작

- Enter 키로도 제출
- 성공 → `unlockAdmin()` → `admin.unlockedAt` 저장 → 대시보드
- 실패 → 입력창 `--warning` 테두리 + "비밀번호가 올바르지 않습니다" (`aria-live`). **흔들림 애니메이션은 넣지 않는다** (디자인 시스템 톤과 불일치)
- 5회 연속 실패 시 30초 입력 잠금 — 실질 보안 효과는 없으나 UX상 오타 인지에 도움
- 세션 유지: 8시간. 만료 시 재입력
- 우상단 `[ 로그아웃 ]`

## 3. 피드백 작성 `/admin/submissions/:id`

프롬프트 12번: *"2단계에서 멘토 요청을 한 상태의 학생들을 실제 피드백 할 수 있게."*

### 3.1 2단 레이아웃

```
┌── 좌: 제출물 (sticky) ──────┬── 우: 피드백 작성 ──────────┐
│ 포트폴리오 프리뷰            │ ① 검증 단계 제어             │
│ (확대 보기 / 원본 열기)      │   현재 4/6  [다음 단계로]     │
│                            │   [즉시 완료 처리]            │
│ 학생 정보                   │                             │
│ · 이름 / 주제               │ ② 원칙별 코멘트 (10개)        │
│ · 제출일                    │   각 원칙 AI 점수 옆 입력창    │
│                            │                             │
│ 요청사항 (2단계 입력)        │ ③ 멘토 종합 코멘트            │
│ "그리드가 흔들리는지…"       │   textarea (필수)            │
│                            │                             │
│ 만족도 응답                 │ ④ 멘토 점수 0–100 슬라이더     │
│ 만족 6 / 동기 7 / 성과 5    │                             │
│                            │ ⑤ 멘토 프로필 선택            │
│ 교육 후기 전문              │                             │
│                            │ [임시저장] [피드백 확정 제출]   │
└────────────────────────────┴─────────────────────────────┘
```

### 3.2 동작

- **좌측이 sticky** — 포트폴리오를 보면서 코멘트를 쓸 수 있어야 한다. 이게 이 화면의 존재 이유다
- 원칙별 코멘트는 선택 입력, 종합 코멘트는 필수
- **임시저장**: 300ms 디바운스로 로컬 초안 보관. 실수로 닫아도 복구
- **확정 제출** → `setMentorFeedback()` → 해당 회차 `status: 'completed'` → 학생의 2단계 모니터가 완료로 전환, 3단계 해금
- 확정 후에는 수정 불가 (확인 모달로 명시)
- 관리자 작성 피드백은 시뮬레이터 더미보다 **우선한다** ([06 §3.5](06-portfolio-step2.md))
- 샘플 시드 항목도 동일하게 피드백 작성 가능 (데모 시연용)

### 3.3 검증 단계 수동 제어

시뮬레이터 타이머를 기다리지 않고 관리자가 단계를 넘길 수 있다.
- `[다음 단계로]` → `advanceMentorStage()`
- `[즉시 완료 처리]` → 6단계 일괄 완료
- 시연 시 유용하고, [06 §3.3](06-portfolio-step2.md) 절대 시각 계산과 충돌하지 않도록 **수동 진행 시 해당 단계의 `completedAt` 을 현재 시각으로 확정**한다
