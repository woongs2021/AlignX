## 2. HERO — "무한으로 넓게 퍼지는" ★

### 2.1 해석

원문의 표현은 두 가지로 읽힌다. **A안을 채택**하고, B안을 폴백으로 남긴다 ([00 §3 Q4](00-overview.md)).

| | A안 — 무한 마퀴 + 스크롤 확산 (채택) | B안 — 단일 이미지 줌아웃 |
|---|---|---|
| 초기 | 화면 중앙, 이미지 3행이 좁게 압축된 상태 | 이미지 1장이 화면을 꽉 채움 |
| 스크롤 | 행 간격·스케일이 벌어지며 **좌우로 무한히 흘러간다** | 스크롤에 따라 축소되며 주변 콘텐츠가 드러남 |
| 인상 | 물량감·확산감. 포트폴리오 아카이브의 은유 | 집중·미니멀 |
| 리스크 | 이미지 10장으로 무한감을 만들어야 함 | 이미지 1장의 품질에 전적으로 의존 |

**A안 선택 이유:** 보유 에셋이 10장이고, "넓게 퍼지는" 이라는 표현이 수평 확산을 직접 가리킨다.

### 2.2 A안 사양

**레이아웃** — 3행 마퀴 스택 (`100dvh`, `overflow: hidden`)

| 행 | 방향 | 속도 | 카드 폭 |
|---|---|---|---|
| 1 | ← 좌 | 60s | 320px |
| 2 | → 우 | 80s | 400px (가장 큼, 시선 중심) |
| 3 | ← 좌 | 70s | 320px |

- 각 행은 이미지 10장 + **복제본 1세트** = 20장. `transform: translateX(-50%)` 무한 루프 (`animation-timing-function: linear`)
- 카드: radius `--r-tile`(28), `object-fit: cover`, 비율 16:10
- `will-change: transform`, `transform: translate3d()` 로 GPU 합성. `left`/`margin` 애니메이션 금지

**스크롤 확산** (`useScroll` + `useTransform`, 구간 `0 → 0.5`)

| 값 | 시작 → 끝 |
|---|---|
| 행 간 gap | `12px → 40px` |
| 전체 스케일 | `1.12 → 0.94` |
| 행 1·3 opacity | `1 → 0.35` (중앙 행으로 시선 수렴) |
| 헤드라인 opacity | `0 → 1` (구간 `0.05 → 0.25`) |
| 오버레이 딤 | `0 → 0.55` |

**헤드라인** (마퀴 위 절대 배치, 중앙)

```
ALIGNX                                   ← --t-label, --primary
PORTFOLIO                                ← --t-display-1, Montserrat 300
데이터로 검증하는 합격 포트폴리오              ← --t-kr-2, Pretendard 400
AI 10대 원칙 분석과 현직 멘토 검증을 한 번에.   ← --t-lead, --fg-muted
[ 포트폴리오 분석 시작 ]  [ AlignX AI 알아보기 ]
```

가독성 확보: 이미지 위 텍스트이므로 `--bg` 기반 라디얼 딤 오버레이를 깔고, 그 위에 텍스트. **텍스트에 그림자를 넣지 않는다** — 딤으로만 해결 (디자인 시스템 §그림자 금지).

**스크롤 힌트** — 하단 중앙 12px 라벨 `SCROLL` + 2px 세로선이 1.6s 주기로 아래로 흐름. 첫 스크롤 시 사라짐.

### 2.3 성능 가드 (필수)

이 히어로는 이 사이트에서 가장 무거운 화면이다.

- 이미지는 **WebP 800/1600 두 사이즈만** 로드 (2400은 히어로에 쓰지 않음) — [01 §3.5](01-setup-infra.md)
- 첫 화면 진입 이미지 6장 `fetchpriority="high"`, 나머지 `loading="lazy"`
- LQIP(24px blur) → 원본 크로스페이드 300ms
- 마퀴 DOM 노드 상한 **60개**. 초과 시 화면 밖 카드 `content-visibility: auto`
- **탭 비활성 시 애니메이션 정지** (`document.visibilityState` 감시) — 배터리 소모 방지
- `prefers-reduced-motion` → 마퀴 정지, 정적 3×3 그리드로 대체 (스크롤 확산도 해제)
- 모바일(<768px): 3행 → **2행**, 카드 폭 220px, 속도 20% 감속

### 2.4 폴백

이미지 로드 실패 시 `--soft` 색면 타일 + 파일명 라벨로 대체. 히어로가 빈 화면이 되는 경우는 없어야 한다.

## 3. ② VALUE

`--tint` 배경 밴드. 중앙 정렬 리드 문장 1개(68ch 제한) + 3개 `StatTile`:

| 지표 | 값(더미) | 라벨 |
|---|---|---|
| 분석 원칙 | `10` | VISUAL & UX PRINCIPLES |
| 검증 단계 | `3` | AI → MENTOR → REPORT |
| 평균 분석 시간 | `90초` | AVERAGE ANALYSIS |

숫자는 `--t-display-3`, 카드 면적의 절반을 차지 (디자인 시스템 §stat-tile).

## 4. ③ HOW IT WORKS

3열 카드. 각 카드 = 큰 번호(`--t-display-3`, `--primary`) + 영문 라벨 + 한글 제목 + 2줄 설명 + 썸네일.

| # | 제목 | 설명 | 썸네일 키 |
|---|---|---|---|
| 01 | AI 분석 | 포트폴리오를 업로드하면 10대 비주얼·UX 원칙으로 90초 안에 채점합니다. | `step1-loading` |
| 02 | 멘토 검증 | 현직 디자이너 멘토가 AI 점수 위에 사람의 관점을 덧댑니다. | `step2-mentor` |
| 03 | 통합 리포트 | AI와 사람의 결론을 한 장으로 묶어 HTML로 내려받습니다. | `step3-report` |

카드 호버: 이미지 `scale(1.03)` **또는** 번호 색 전환 — [03 §2.3](03-layout-navigation.md) "한 요소에 한 가지 호버 신호" 원칙에 따라 **이미지 스케일 하나만** 채택.

## 5. ④ PRINCIPLES 프리뷰

[00 §8](00-overview.md) 10대 원칙을 5×2 그리드 pill 배지로 나열. 각 배지 = 번호 + 한글명 + 영문명.
호버 시 해당 원칙의 한 줄 정의가 하단 고정 영역에 표시 (툴팁 금지 — 모바일에서 무력하다).
하단에 `AlignX AI 자세히 보기 →` 링크 → `/alignx`.

## 6. ⑤ SHOWCASE

3단계 최종 리포트를 축소한 목업 카드 (`--deep` 배경, 반전 텍스트).
- 좌: 총점 `87` (`--t-impact`, **이 페이지에서 weight 700이 등장하는 유일한 자리**)
- 우: 10개 원칙 막대 그래프 — 단색 면, 격자·그라디언트 없음
- 하단: 멘토 코멘트 1줄 인용

> 디자인 시스템 §Do "weight 700은 페이지당 한 번" — HOME에서는 여기에만 쓴다.

## 8. 완료 기준

- [ ] 히어로가 끊김 없이 무한 루프(이음매 육안 확인 불가)
- [ ] 스크롤에 따라 확산 → 헤드라인 등장이 자연스럽고 역방향 스크롤에서도 정상 복원
- [ ] Chrome Performance: 히어로 스크롤 중 **평균 55fps 이상**, 롱태스크 없음
- [ ] LCP < 2.5s (Slow 4G 스로틀), 히어로 이미지 총 전송량 **2MB 이하**
- [ ] `prefers-reduced-motion` 에서 정적 그리드로 대체
- [ ] 360px / 768px / 1440px 전부 히어로 텍스트 가독성 확보
- [ ] 라이트/다크 양 모드에서 이미지 위 텍스트 대비 4.5:1 이상
- [ ] 탭 비활성 시 애니메이션 정지 확인
- [ ] weight 700 사용 1회(⑤ 총점)뿐임을 확인
