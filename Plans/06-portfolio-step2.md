## 2. `form` — 제출 양식

### 2.1 첨부 문서 (읽기 전용)

프롬프트 원문: *"기존에 넣었던 문서가 그대로 붙여져서 제출 양식을 정하게 되"*

폼 최상단에 1단계 파일이 **이미 첨부된 상태**로 고정 표시한다.

```
┌─────────────────────────────────────────────┐
│ [프리뷰]  001_포트폴리오.pdf                  │
│           PDF · 12.4MB · AI 총점 87점 (A)    │
│           1단계에서 분석한 문서가 그대로 첨부됩니다  │
└─────────────────────────────────────────────┘
```

여기서 파일을 바꿀 수 없다. 바꾸려면 1단계로 돌아가 새 회차를 만든다 — 분석 점수와 제출 문서의 동일성을 보장하기 위함.

### 2.2 입력 필드

| # | 라벨 | 타입 | 검증 |
|---|---|---|---|
| 1 | 이름 | text | 필수 · 2–20자 |
| 2 | 주제 | text | 필수 · 2–60자 (예: "커머스 앱 리디자인") |
| 3 | 멘토에게 요청하는 사항 | textarea | 필수 · 10–500자 · 실시간 카운터 |

textarea: radius `--r-lg`, 패딩 `--sp-xl`, 우하단 카운터. 480자 초과 시 카운터가 `--warning` 으로 전환.

### 2.3 7점 척도 3항목

프롬프트 원문: *"교육 만족도/동기부여/학습성과 3가지 항목을 7점 척도로"*

| id | 라벨 | 좌측 앵커 | 우측 앵커 |
|---|---|---|---|
| `satisfaction` | 교육 만족도 | 전혀 그렇지 않다 | 매우 그렇다 |
| `motivation` | 동기부여 | 전혀 그렇지 않다 | 매우 그렇다 |
| `outcome` | 학습성과 | 전혀 그렇지 않다 | 매우 그렇다 |

**구현:** `<fieldset>` + `<legend>` + `radiogroup`, 1–7 원형 노드 가로 배열.
- 노드 44×44 히트 영역 (터치 타깃 기준)
- 선택 시 `--primary` 채움, 좌측 노드들은 `--soft` 로 연결되는 게이지 표현
- **키보드 좌우 화살표로 이동 가능** (네이티브 radio 그룹 동작 유지 — 커스텀 div로 만들면 접근성이 무너진다)
- 모바일: 7개가 가로로 안 들어가면 노드 크기 축소 대신 **숫자만 표시 + 앵커 라벨을 위아래로 분리**
- 3항목 모두 필수

### 2.4 주관식 교육 후기

textarea, 필수, 10–1000자. 플레이스홀더: "수업에서 가장 도움이 된 점, 아쉬웠던 점을 자유롭게 적어주세요."

### 2.5 제출

`[ 최종 포트폴리오 제출 ]` — 전 필드 유효할 때만 활성.

- 검증 실패 시 **첫 오류 필드로 스크롤 + 포커스**, 필드 하단에 `--warning` 메시지, `aria-invalid` + `aria-describedby`
- 제출 전 확인 모달: "제출 후에는 수정할 수 없습니다. 진행할까요?"
- 제출 시 `mentorRequest` 저장 + `status: 'submitted'` + `mentorStages` 초기화
- 자동 임시저장: 입력 300ms 디바운스로 로컬 초안 보관 → 실수로 나가도 복구

## 3. `monitoring` — 실시간 검증 모니터 ★

프롬프트 원문: *"멘토들이 000님의 포트폴리오를 검증하고 답변을 드립니다."* + *"어느 단계에서 검증 중인지 실시간으로 모니터링"*

### 3.1 헤드

```
MENTOR VERIFICATION                       ← --t-label
{이름}님의 포트폴리오를 멘토들이 검증하고 있습니다   ← --t-kr-2
제출 2026. 8. 9. 오후 3:12 · 예상 완료 약 3분 후
```

### 3.2 6단계 타임라인

| # | 단계 | 담당 멘토(더미) | 소요 |
|---|---|---|---|
| 1 | 접수 확인 | 시스템 | 6s |
| 2 | 멘토 배정 | 운영팀 | 12s |
| 3 | 1차 리뷰 — 구조 · 내러티브 | 김세연 · UX Lead | 40s |
| 4 | 2차 리뷰 — 비주얼 · UX | 박도현 · Product Designer | 40s |
| 5 | 종합 코멘트 작성 | 이지우 · Design Director | 50s |
| 6 | 검증 완료 | — | — |

총 약 **2분 30초**. 데모 시연용으로 `?fast=1` 쿼리 파라미터를 붙이면 10배 가속 (개발/시연 편의).

**표현 — 세로 타임라인**
- 좌측 세로선 + 단계별 노드. 완료 `--primary` 채움 / 진행 `--primary` 링 + 펄스 / 대기 `--mute` 외곽선
- 진행 중 단계만 카드가 펼쳐져 멘토 아바타(40px 원형, 모노톤) + 이름 + 역할 + 현재 작업 문구 표시
- 완료 단계는 접혀서 체크 + 완료 시각(`--font-mono`)만
- 상단 전체 진행률 ProgressBar + "3 / 6 단계 진행 중"

### 3.3 시뮬레이터 설계

```ts
// src/features/mentor/simulator.ts
export function resumeMentorProgress(attempt: Attempt, now = Date.now()): MentorStage[];
```

**절대 시각 기준으로 계산한다.** `setInterval` 카운터를 상태로 들고 있으면 탭을 닫았다 열 때 진행이 멈춰 있거나 튄다.

- 각 단계에 `startedAt` 절대 시각을 부여 → 현재 시각으로 진행 단계를 **역산**
- 렌더 갱신용 `setInterval(1000)` 은 화면 표시만 담당
- 탭 복귀(`visibilitychange`) 시 즉시 재계산 → 3분 뒤 돌아와도 "완료" 상태로 정확히 표시
- 마지막 단계 완료 시 `mentorFeedback` 생성(더미) + `status: 'reviewing' → 'completed'`

### 3.4 완료 처리

- 완료 카드가 `--primary` 풀블리드로 전환 + `[ 3단계 · 통합 리포트 보기 → ]` 활성
- 전환 순간 `role="status"` 로 "멘토 검증이 완료되었습니다" 안내
- 이 화면을 떠나도 진행은 계속된다. MY 페이지·ADMIN에서 동일 상태를 조회할 수 있어야 한다

### 3.5 ADMIN 연동

[10-admin.md](10-admin.md) 에서 관리자가 **수동으로 단계를 진행**시키거나 **실제 코멘트를 작성**할 수 있다.
- 관리자가 작성한 피드백이 있으면 더미 피드백 대신 그것을 사용한다
- 우선순위: `관리자 작성 피드백 > 시뮬레이터 더미 피드백`
- 동일 `localStorage` 를 공유하므로 같은 브라우저에서만 연동된다 (제약을 화면에 명시)

### 3.6 더미 멘토 피드백

`src/data/mentors.ts` — 멘토 3인 프로필 + 원칙별 코멘트 풀.
멘토 점수(`mentorScore`)는 AI 총점 ±8점 범위에서 결정론적으로 생성 → 3단계에서 "AI와 사람의 관점 차이"를 보여주는 재료가 된다.

## 4. 완료 기준

- [ ] 1단계 파일이 폼에 자동 첨부되고 교체 불가
- [ ] 필수 5개 영역(이름·주제·요청사항·7점척도 3개·후기) 검증 동작, 첫 오류로 포커스 이동
- [ ] 7점 척도가 **키보드 화살표로 조작** 가능하고 스크린리더가 항목명·값을 읽음
- [ ] 제출 후 "OOO님의 포트폴리오를 멘토들이 검증하고 있습니다" 화면 표시
- [ ] 타임라인 6단계가 순서대로 진행, 현재 단계가 시각적으로 명확
- [ ] **탭을 닫고 3분 뒤 재진입 시 완료 상태로 정확히 복원**
- [ ] `?fast=1` 로 가속 시연 가능
- [ ] 완료 시 3단계 버튼 활성 + 안내 낭독
- [ ] 임시저장 초안이 새로고침 후 복구
- [ ] 웜톤 단독 사용 — 이 페이지에 cool 계열 토큰 미사용
